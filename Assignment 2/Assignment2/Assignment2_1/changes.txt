    In draw(), is_back_facing is called after the full MVP transform and perspective divide:

  Eigen::Matrix4f mvp = projection * view * model;  // view = camera!
  // ...vertices transformed by mvp, then perspective divide...
  bool back_facing = is_back_facing(v);  // v is already in screen space

  The view matrix (which encodes the camera orientation) is baked into mvp. So when the camera rotates, the screen-space positions of the vertices change,
  and the winding order the function measures automatically reflects the new camera angle. You don't need to pass the camera explicitly.

  However, there is one real issue: when a vertex goes behind the camera, the perspective divide flips its coordinates (because w < 0), which can
  incorrectly flip the winding order for triangles that straddle the near plane — making a front-facing triangle look back-facing and get wrongly culled.

  The proper fix for that edge case is to cull using the view-space normal instead of screen-space winding:

  // In view space, before projection
  // face normal dot view direction <= 0 → back-facing

  But this requires restructuring the draw loop. For now, with the bounds-check fix in place, those degenerate triangles simply won't render (rather than
  crashing), which is acceptable behavior.

  1. Compute the signed area
    - After the MVP transform and viewport mapping, compute the 2D signed area of the triangle using the cross product of two screen-space edge vectors:
  signed_area = (v1 - v0) × (v2 - v0)
    - A positive signed area means the vertices wind counter-clockwise (CCW) → the triangle is front-facing.
    - A negative signed area means the vertices wind clockwise (CW) → the triangle is back-facing.
  2. Apply the cull mode
    - CullMode::None — no triangle is discarded; all triangles proceed to rasterization.
    - CullMode::Back — triangles whose signed area is negative (CW / back-facing) are skipped.
    - CullMode::Front — triangles whose signed area is positive (CCW / front-facing) are skipped.
  3. Skip or continue
    - If the triangle passes the cull test (or culling is disabled), it is forwarded to rasterize_triangle.
    - If it fails the cull test, it is discarded entirely — no pixels are touched and no depth or color writes occur for that triangle.
